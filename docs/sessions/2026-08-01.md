## Decisions
- **Clean single-commit import** (no history transfer) — extraction files are small; history stays in the child repo.
- **Palette-agnostic theme builders**: identity (AppPalette, ColorScheme seeds, `app_theme.dart`) stays per project; commons supplies only the shared component-building machinery.
- **Contract-driven screens (grandeur pattern)**: package ships presentational screen + abstract contracts (`Strings`/`AsyncData`/`ServiceCallbacks`) in a `part of` file; apps implement + inject. Screen stays framework-free (ValueNotifier only) — bloc/routing/localization live app-side. Login is the first contract-driven screen; data layer (AuthService/model/cubit/mock/DI) stays per-fork by design (user: models never go to commons).
- **Name collisions are intentional**: commons shadows material classes (`FilledButton`, `IconButton`, `OutlineButton`, `Title`); consumer convention = `material as m` or `hide` (documented in README).
- **Consumption pattern**: committed git dep `commons @ ref: vN` in each consumer; `pubspec_overrides.yaml` (gitignored) overrides locally for development — khelam uses an absolute path, forkable a relative `../commons`.
- **No `!` rule is repo-wide** (user, 2026-08-01): applies to all Flutter apps we build — hand-written code only; generated freezed files exempt.
